# Annmary Brown Memorial collection

This repository intentionally contains both:

- the editable source for a Zola site; and
- the matching generated site in `public/`.

Keeping both allows the repository to function as a ready-to-deploy static
website while retaining the structured material needed for later editing.
Source changes and their regenerated `public/` output should be reviewed and
committed together.

The site uses [Zola](https://www.getzola.org/) 0.22.1 and a vendored,
commit-pinned snapshot of [tabi](https://github.com/welpo/tabi). See
`THEME.md` for the exact theme revision.

## Source layout

- `content/` contains narrative pages and the individual collection pages.
- `data/collection_records.json` contains the structured catalog data used by
  collection and browse templates.
- `static/search/collection-records.json` contains the smaller browser-search
  dataset.
- `templates/` contains the collection-specific layouts.
- `static/amb.css` contains the collection-specific styling.
- `static/js/` contains the collection-search interface.
- `static/images/` contains the web-ready images copied into the built site.
- `assets/` retains source images used to prepare the web-ready derivatives.
- `themes/tabi/` is the pinned third-party visual theme.
- `public/` is generated by Zola and should not be edited manually.

Collection metadata currently has coordinated representations in
`data/collection_records.json`, `content/collection/`, and
`static/search/collection-records.json`. Keep those representations consistent
when changing a collection record.

Legacy conversion inputs are deliberately kept outside this repository.
Internal administrative and appraisal data are not included in the collection
pages or browser-search dataset.

## Search design

The collection search uses Elasticlunr, the Lunr-family search library used by
Zola. It is collection-specific rather than a generic all-page index.

Only these fields are searchable:

- artist;
- title;
- nationality.

The compact search dataset also carries the item identifier, artist dates,
image path, and record slug. Those values support useful result cards but are
not registered as searchable fields.

Search combines Elasticlunr word matching with a direct case-insensitive
substring pass across the same three fields. This preserves the useful behavior
of the former catalog search while retaining Lunr-style matching. Results are
sorted by artist and displayed in manageable batches.

## Requirement

Use Zola 0.22.1. Confirm the active executable with:

```sh
zola --version
```

The required version is also recorded in `.zola-version`.

## Preview

From the repository root, run:

```sh
zola serve --output-dir .work/serve
```

Then open the local address printed by Zola. The explicit output directory
keeps preview files separate from the production files tracked in `public/`.

## Check the site

Use Zola's built-in checker before a production build:

```sh
zola check
```

This checks the content, templates, and links that Zola can validate.

## Build `public/`

Create a production build with:

```sh
zola build
```

The `output_dir` setting in `zola.toml` directs the result to `public/`, and
the production `base_url` ensures generated links work below
`/collections/amb/`.

Zola recreates generated output during a build. Review changes under both the
editable source and `public/` before committing.

## Routine editing

- Narrative pages: edit Markdown under `content/`.
- Individual collection pages: edit the corresponding
  `content/collection/ab-N/index.md` file and keep the structured catalog and
  search datasets synchronized.
- Layouts: edit files under `templates/`.
- Styling: edit `static/amb.css`.
- Collection search logic: edit `static/js/collection-search-core.js`; browser
  rendering and interaction live in `static/js/collection-search.js`.
- Theme updates: replace the vendored snapshot deliberately and update
  `THEME.md`. Keep collection-specific work outside `themes/tabi/`.

After editing, run:

```sh
zola check
zola build
```

## Editorial notes

- Catalog wording, uncertain dates, historical attributions, and legacy
  punctuation are preserved unless an editor deliberately changes them.
- Image alternative text is currently generated from title and artist. It is a
  useful fallback, not a substitute for future image-description work.
- Room, location, inventory, and reproduction-format values reflect reviewed
  legacy public data and may need periodic curatorial review.
- Narrative pages link to Brown University Library for current visitor and
  permissions information instead of embedding details that can become stale.

## Deployment

The production setting is:

```toml
base_url = "https://library.brown.edu/collections/amb"
```

Deploy only the contents of `public/`, not the repository root. No
compatibility mapping for the former dynamic URLs is included.
